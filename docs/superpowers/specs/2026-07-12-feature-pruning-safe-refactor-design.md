# GTA5 DMA 功能精简与安全重构设计

## 目标

在不改变当前 ImGui 双栏布局、视觉主题、窗口尺寸和保留功能行为的前提下，停用时间、任务/分红和追战局三个无用模块，并对根目录下的 GTA5 DMA 主工程进行保守结构优化。优化重点是代码职责、DMA 读写边界、失效地址清理和可验证性，而不是重写功能或更换架构。

## 功能停用范围

### 时间控制

- 从左侧导航移除“时间”。
- 页面路由不再进入时间页面。
- DMA 主循环不再调用 `TimeControl::OnDMAFrame()`。
- `TimeControl.h/.cpp`、页面渲染函数、枚举值和工程文件条目继续保留。
- 在导航、路由和 DMA 调用原位置保留注释，说明模块被停用以及恢复方式。

### 任务与分红

- 从左侧导航移除“任务”。
- 页面路由不再进入任务/分红页面。
- DMA 主循环不再调用 `HeistDividend::OnDMAFrame()`。
- `HeistDividend.h/.cpp`、页面渲染实现、枚举值和工程文件条目继续保留。
- 不删除任务预设、分红读取和写入代码。

### 追战局

- 从设置页面移除“启用追战局”开关。
- DMA 主循环不再调用 `PlayerChaser::OnDMAFrame()`。
- 保留 `PlayerChaser` 和 `PlayerChaserMenu` 的源文件、实现、声明和工程条目。
- 停用时确保其开关保持关闭，避免以后其他路径意外调用时恢复旧状态。

## UI 不变量

- 保持当前 900x620 默认大小和 760x520 最小大小。
- 保持顶部状态栏、左侧快速控制、左侧模块导航、右侧参数区域和底部状态栏。
- 保留人物、载具、武器、传送和设置页面。
- 不修改主题颜色、字体、控件风格和菜单快捷键。
- 不增加新的仪表盘、动画或页面布局。

## 保守结构优化范围

### 页面路由清理

`ConsoleShell` 继续作为主界面协调器。导航项目和页面路由使用同一份“启用页面”定义或紧邻的集中定义，避免以后出现导航已隐藏但页面仍可进入的情况。停用页面保留枚举和渲染函数，不从工程删除。

### 大型 UI 文件拆分

仅拆分职责明确且可以保持公开接口不变的代码：

- 将人物、武器、传送、载具和设置页面内容从 `MenuManager.cpp` 拆到按页面命名的实现文件。
- `MenuManager.h` 的现有公开函数签名保持不变。
- 不在拆分过程中修改控件绑定、默认值和功能调用。
- `VehicleEditor.cpp` 本轮只做审计和局部辅助函数提取，不进行大规模功能重写；其 80KB 级拆分作为独立后续阶段，避免与 DMA 读写修复混合。

### DMA 读写边界

- 保留 `DMA::UpdateEssentials()` 作为核心地址快照更新入口。
- 所有功能在访问 DMA 前检查句柄、PID、基址和所需目标地址。
- 读取必须检查 API 返回值和实际读取字节数。
- 写入必须检查 API 返回值，不把失败写入报告为成功。
- 下车、人物重生、战局切换、游戏关闭或关键指针读取失败时，相关缓存地址立即清零。
- 不改变现有偏移、写入数值、响应频率和功能语义。

### 无意义访问控制

- 已停用的时间、任务和追战局不再进入 DMA 主循环。
- 其余功能仅在自身开关或必要状态启用时执行昂贵读写；基础状态更新可以继续执行。
- 不为了减少读写而降低现有功能的可感知响应速度。
- 每项访问优化必须能说明关闭状态下省略了什么操作，并有构建或契约验证。

## 代码可视化与文档

新增源码结构说明文档，包含：

- 主线程、DMA 线程和 ImGui 帧之间的数据流图。
- `DMA::UpdateEssentials()` 到各功能 `OnDMAFrame()` 的调用关系。
- 人物、载具、武器、传送所依赖的地址快照。
- 功能开关、读取、写入和 UI 状态之间的关系。
- 已停用模块的恢复步骤。

可视化使用 Mermaid，保存在项目文档中，不改变程序运行界面。

## 分阶段实施

### 阶段一：停用三个模块

只修改导航、页面路由、设置内容和 DMA 调用。添加契约测试，验证三个入口和后台调用均不存在，同时源文件和工程条目仍然存在。完成 Release x64 构建。

### 阶段二：DMA 安全审计

审计主工程中的 `VMMDLL_MemReadEx`、`VMMDLL_MemWrite` 和 Scatter 调用。优先修复未检查返回值、读取字节数不完整、失效地址未清理和关闭功能仍持续写入的问题。每次只修一个模块并构建。

### 阶段三：页面实现拆分

在公开接口和 UI 输出不变的前提下拆分 `MenuManager.cpp`。每迁移一个页面就运行契约测试和 Release 构建，不同时修改功能逻辑。

### 阶段四：结构文档和最终验证

补充 Mermaid 数据流图、模块关系图和人工回归清单。运行全部自动测试、契约测试、`git diff --check` 和 Release x64 构建。

## 验证策略

### 自动验证

- 导航中不出现时间和任务入口。
- 页面路由不调度时间和任务页面。
- 设置页面不出现追战局开关。
- DMA 主循环不调用三个停用模块。
- 三个模块的源文件、类和工程条目仍然存在。
- 人物、载具、武器、传送和设置页面仍可路由。
- F5 标点传送和 Insert/End 快捷键绑定仍然存在。
- Release x64 构建为 0 错误。

### 实机验证

- DMA 初始化和 Enhanced/原版识别正常。
- 人物、载具、武器和传送读写正常。
- 上下车、死亡重生、换战局和游戏重启后地址恢复正常。
- 已停用功能不产生后台读写。
- Insert 隐藏、F5 传送和 End 退出正常。

## 风险控制

- 不修改偏移值。
- 不修改游戏数值常量。
- 不删除停用模块代码。
- 不一次性重写 `VehicleEditor.cpp`。
- 不修改历史副本、第三方 ImGui 或 MemProcFS 文件。
- 不覆盖工作区内用户已有的未提交修改。
- 无法在当前环境中替代真实 DMA 硬件和 GTA 实机验证，因此最终读写行为需要按回归清单在目标环境确认。

## 验收标准

- UI 外观保持不变，只减少时间、任务和追战局三个入口。
- 三个模块不再执行后台 DMA 访问，代码仍可恢复。
- 保留功能的调用路径、数值和快捷键不变。
- 关键 DMA 读写具备明确的地址和返回值保护。
- 页面代码职责比当前更清晰，文档能直观看到线程、地址和功能关系。
- 自动测试和 Release x64 构建通过，实机回归清单完整。
